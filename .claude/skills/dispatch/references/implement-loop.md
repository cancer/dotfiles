# implement のループ（合意版、2026-11-09）

implement の作業を「人が決める部分（計画）」と「人を待たずに回る部分（ループ）」に分ける。ループは dev-workflow が担う。用語の「ループ」は、ゴールが固定されていて人を待たずに回るものを指す。

## 流れ

1. 主スレッド（companion）が dispatch で依頼を State に固定する
2. 主スレッドが `plan` を呼び、入力（タスク・完了条件・契約）を作らせる
3. 実測が要る仮定があれば、`plan` は計画を作らず主スレッドへ差し戻す。主スレッドは PoC を `dev-workflow --effort low` で渡し、返ってきた生の出力で合否を判定する。「成立しない」で決着したら、方針をユーザーと決め直す。決着したら 2 へ戻る
4. ユーザーが計画を承認する
5. 主スレッドが承認済みの計画と effort を dev-workflow に渡す
6. dev-workflow はループを回し、作業ブランチへの統合とコミットで終える。PR は作らない。PR が要るかは主スレッドが決め、`create-pr` を呼ぶ

人が介入するのは 1〜4 と、ループを抜けて返ってきた後だけである。ループの中では人に諮らない。

## 入力の形（plan の出力 = dev-workflow の入力）

計画と全体設計は dev-workflow の外で決まっている前提とする。dev-workflow はタスクの分解・依存の判断・設計判断をしない。

```markdown
# 計画: <タイトル>

## タスク

### T1: <タスク名>
- 対象: <変更・作成するファイル>
- 完了条件:
  - p1_<短い名前>: <命題を 1 文で>
  - p2_<短い名前>: <命題を 1 文で>
- 契約: 提供 C1 / 利用 なし

### T2: <タスク名>
- 対象: ...
- 完了条件:
  - p1_<短い名前>: ...
- 契約: 提供 なし / 利用 C1

## 契約

### C1: <契約名>
- 提供: T1 / 利用: T2
- 内容: <型・関数シグネチャ・API のパスと入出力・スキーマ・イベント・エラー種別・命名>
```

- 完了条件の各行は、verify-task の `propositions.json` の `statement` にそのまま写せる命題である。dev-workflow はタスクごとにこれを `propositions.json` に書き、verify-task に命題を導かせない
- タスク間の依存は書かない。依存は契約で切り、全タスクを並列に回す。契約を結べない組は、計画の側で 1 つのタスクにまとめる
- 実測が要る仮定は、この計画には含まれない（含まれていれば 3 で差し戻されている）

## effort

effort は品質をどの軸で評価・改善するかを表す。選んだ軸は指摘が無くなるまで回す（上限 3 周）。effort は主スレッドが会話から判断して渡す。

| effort | 回す軸 | 拾う指摘 | テスト |
|---|---|---|---|
| low | なし。実装して実測の生の出力を返す | ― | 書かない |
| mid | verify-task、test-review | 重要度 high / mid | TDD |
| high | verify-task、test-review、code-review、統合後レビュー | low まで | TDD |

- verify-task は「できているか、いないか」の二値なので、拾う範囲の対象外。FAIL・判定不能は常に拾う
- low は PoC 用である。PoC の完了は仮定が決着したことで、成立・不成立のどちらも完了なので、verify-task も回さない

## ループを抜けるとき

次の事態では、ループを抜けて状況を呼び出し側（主スレッド）へ返す。原因は入力の側にあるので、直すのは計画を作る側である。

- effort が無い、委任経路が使えないなど、入力・環境の不備
- 3 周で収束しない
- 指摘の矛盾が既定の解決順で解けない
- 実装中に契約が成立しないと分かった
- 推論量 max でも進まない
- 統合の調整方針を判断できない
- 指示と反する判断が要る
- サンドボックス外の操作を頭脳が代行しようとして拒否された（権限設定・classifier による拒否）

抜けるときは何も統合せず、全タスクの worktree とブランチを残して返す。計画が直されると、検収を通ったタスクも前提が変わって無効になりうるためである。

サンドボックス外の操作は、原則として頭脳が代行する。代行しても拒否された操作だけが、上記の抜ける条件になる。
