After the selected task passes verification, run-plan.md calls create-pr for the PR deliverable, then watch-ci with the PR URL or number. It checks the reported success or failure and, on failure, the check name, type, cause, and log excerpt. A CI failure is sent as a finding to a new thread; after the fix, run-plan.md starts a fresh-thread Phase 3 re-verification against the final tree. The head itself reruns the mechanical lint/format, type, and test checks. verify-task and test-review each run again in a new thread separate from the implementer. No earlier PASS result is reused. Each CI failure/fix/re-verification cycle counts toward the three-round limit.
