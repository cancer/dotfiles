The implementer commits the task result to feature/counter-version (commits are allowed within the request's git-operation scope). After verification passes, run-plan.md has the head confirm that the result is committed on feature/counter-version (e.g., via git log) and ends there; the head does not make the commit itself. It does not call create-pr or watch-ci and does not create a PR.
