タスク定義に記載された契約順に成果物を統合する。マージの確認・承認はユーザーに求めない。

## 引数

$ARGUMENTS

- タスク定義ファイルのパス
- タスクごとの成果物。`T<n>=<PR URL またはブランチ名>` の形で指定する
- `--effort low|mid|high`。値は呼び出し側から受け取り、自分では決めない

タスク定義は C2 の形式であること。各タスクの `pN_deliverable` と引数の成果物をタスク ID で対応させる。成果物の命題が無い PoC タスクはマージ対象に含めない。

## 手順

### 1. マージ順を決める

タスク定義の「契約」節から、タスク間の依存を読み取る。あるタスクが契約を提供し、別のタスクが利用する場合は、提供側を先にする。依存関係を満たす順序の中で、次に処理できるタスクが複数あれば、タスク ID の数値が小さい順にする。

### 2. 成果物を順に統合する

決めた順序で、各タスクの成果物を処理する。先行タスクの統合後に次のタスクへ進む。

effort が `high` なら、最初のマージ前に統合対象 base の参照先と commit を記録する。PR の base は PR 情報から確認し、ブランチ成果物は現在の作業ブランチを base とする。

#### 成果物が PR の場合

1. `gh pr update-branch <PR>` でこの PR のブランチを最新の base に追従させる。先行 PR があれば、そのマージを含む最新の base に追従させる。
2. `/Users/cancer/.claude/skills/watch-ci/SKILL.md` の C6 に従って CI を待つ。C6 の待機は `gh pr checks <番号> --watch --fail-fast` で行う。
3. CI が成功した場合だけ `gh pr merge <PR> --merge` でマージする。squash は使わない。

CI が失敗した場合は C6 の返り値（失敗したチェック名・種別・原因・ログ抜粋）を根拠として記録し、そこで止める。

#### 成果物がブランチの場合

タスクのブランチを現在の作業ブランチへ、順序どおり `git merge --no-ff <ブランチ名>` でマージする。プロジェクトにテストコマンドがあれば、各マージの成功後に実行する。テストが失敗したら、C5 の種別を `CI 失敗` とし、実行コマンドとログを根拠としてそこで止める。

### 3. effort high のときだけ結合レビューを行う

全タスクのマージが成功した場合に限り、effort が `high` ならマージ前の base と全マージ後の base の結合 diff をレビューする。effort が `low` または `mid` なら結合レビューを行わない。

記録した commit から全マージ後の base までの結合 diff をレビュー対象にする。`/Users/cancer/.claude/skills/code-review/skill.md` を、マージ作業を行ったスレッドとは別のスレッドから `/Users/cancer/.claude/skills/delegate-to-codex/SKILL.md` 経由で実行する。読み取り専用で、統合対象の作業ツリーを指定する。委任依頼には結合 diff と対象の base を含める。

依頼文では、レビュー観点を次の結合特有の整合性に限定する。

- 同一ファイルのマージ後の不整合
- API・型・スキーマの食い違い
- 設計方針の矛盾、命名の不一致
- 重複実装、重複テスト

タスク単体の品質は `dev-workflow` の検収で済んでいるため、結合レビューではタスク単体の品質観点を繰り返さない。この限定理由も依頼文に明記する。

## 失敗時

CI の失敗、PR またはブランチのマージ競合、または結合レビューの指摘があれば、その時点で処理を止める。競合の解消を含め、コードやブランチの修正は行わない。後続タスクのマージも続けない。ユーザーに確認・承認を求めず、C5 の失敗形式で companion に返す。修正は companion が原因タスクの `dev-workflow` を回し直して行う。

## 返すもの

完了時は、マージ済みのタスク ID と成果物を一覧で返す。

失敗時は、C5 に従い次を返す。

- 原因タスク ID
- 種別: `CI 失敗` / `競合` / `結合レビューの指摘`
- 根拠: 失敗ログ、テスト出力、またはレビュー指摘本文
- 未マージのタスク一覧

原因タスクが複数にまたがる場合は、根拠を対応づけて該当する ID をすべて記す。結合レビューの指摘後は全マージ済みであるため、未マージ一覧は空と記す。

## 参照する契約

- 提供: C5
- 利用: C0, C2, C6
- C0 のスキル参照は `/Users/cancer/.claude/skills/<名前>/SKILL.md`、タスク定義形式は `/Users/cancer/.claude/skills/run-implement/references/task-format.md` である。
- C5 の完了時はマージ済み一覧を返し、失敗時は原因タスク ID・種別・根拠・未マージ一覧を返す。
- C6 の CI 失敗時は、失敗したチェック名・種別・ログから読み取った原因・該当ログ抜粋を根拠に含める。
