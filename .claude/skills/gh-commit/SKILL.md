未コミットの変更を論理単位に分割して commit する。
**push・PR作成はこのスキルの責務外**（push/PRは `/create-pr` を使う）。staging と commit までで終わる。

## 引数
$ARGUMENTS

引数 = **コミット対象のファイルパス**（複数可）。ユーザーが「コミットしてよいファイル」を明示するためのもの。

この引数がコミット対象を限定する**唯一の根拠**である。作業中ファイルとコミットしてよいファイルをスキル側で推測判別することはできないため、対象はユーザーが引数で指定する。

- 引数で指定されたファイル**だけ**をコミット対象とする。引数にないファイルは、未コミット変更があってもステージ・コミットしない
- 引数が省略された場合: `git status` を提示し、**どのファイルをコミットするかユーザーに確認する**。推測で全変更をコミットしてはならない

---

# ステップ1: 変更の有無を確認

```bash
git status --porcelain
```

出力が空（未コミット変更なし）の場合、その旨を報告して**終了**する。コミットすべきものがないのにコミットを作ってはいけない。

# ステップ2: コミット対象の確定

引数で指定されたファイルパスをコミット対象（以下「対象ファイル」）とする。

- 引数が省略されている場合は、`git status` を提示してどのファイルをコミットするかユーザーに確認し、その回答を対象ファイルとする
- 対象ファイルが実際に未コミット変更を持つことを `git status` で確認する。変更のないパスが指定されていればユーザーに指摘する

# ステップ3: 変更内容の把握

対象ファイルの変更内容を把握する。

```bash
git diff -- <対象ファイル...>           # unstaged
git diff --cached -- <対象ファイル...>  # staged
```

# ステップ4: 論理単位へのグルーピング

対象ファイルを「論理的に1つのまとまり」ごとにグループ化する。判断の観点:

- 同じ機能・関心事に属する変更は同じグループ
- 異なる関心事（例: 機能追加とは無関係なリファクタ、設定変更、typo修正）は別グループ
- 1ファイルが複数の関心事を含む場合は、必要に応じて `git add -p` でハンク単位に分割する

対象ファイルが1つ、または明らかに単一の関心事であれば、分割せず1コミットでよい（速度優先）。

# ステップ5: グループごとに commit

各グループについて、以下を繰り返す。

1. そのグループに属するファイル（またはハンク）だけをステージングする
   - パス指定の `git add <path>...` を使う
   - `git add -A` / `git add .` は無関係な変更や機密ファイルを巻き込むため使わない
2. **混入チェック（必須・スキップ禁止）**: ステージ後、ステージ内容が引数の対象ファイルだけであることを必ず検証する（詳細はステップ5.1）
3. 変更内容を表す簡潔なメッセージで commit する
   - メッセージ形式は自由。変更が何をするものか（または何を直したか）が一読で分かること
   - 規約（Conventional Commits 等）の強制はしない

## ステップ5.1: 無関係なファイルの混入チェック（必須）

**このチェックを実行せずに commit してはならない。** 引数で指定されていないファイル（作業中ファイル等）を無自覚にコミットへ混入させる事故を防ぐための安全ネットである。

各 commit の直前に必ず実行する:

```bash
git diff --cached --stat   # これからコミットされるファイルの一覧
```

`--stat` に並んだファイルを引数の対象ファイル集合と照合する。**対象ファイル以外が1つでも含まれていたら、commit を中断する。** 特に以下に注意する:

- 引数に指定されていないファイル（別タスクの作業中ファイル、デバッグ用の一時変更、`console.log`/`print` 等の消し忘れ）
- 意図しない自動生成物（ビルド成果物、ロックファイルの想定外変更、フォーマッタによる広域差分）
- 機密情報を含みうるファイル（`.env`、鍵、認証情報、個人設定）

中断時の対応:
1. 混入していたファイルの一覧をユーザーに提示する
2. `git restore --staged <path>` でアンステージし、対象から外す
3. 推測で「たぶん一緒でよい」と判断して続行することを禁止する

# ステップ6: 結果報告

- 作成した各コミットの `git log --oneline` 相当（ハッシュ + メッセージ）
- グループ分けの根拠（どの変更をなぜまとめた/分けたか）
- ステージせず残した変更があればその一覧と理由
- push/PR が必要な場合は `/create-pr` を使う旨を案内する（対象ブランチが現在のブランチと異なるなら `--branch <name>` を添える）

# 注意事項

- コミット対象は引数で指定されたファイルのみ。引数にないファイルは未コミット変更があってもコミットしない
- 引数が省略された場合は推測せず、`git status` を提示してユーザーに対象を確認する
- push・PR作成は行わない。それらは `/create-pr` の責務
- `git add -A` / `git add .` は禁止。常にパス（またはハンク）を明示してステージングする
- 機密情報を含むファイルを混入させない。疑わしい場合はユーザーに確認する
- `git commit --amend` や `git push --force` 等、履歴を書き換える操作はユーザーの明示的な許可がない限り行わない
- 現在の作業ディレクトリが対象リポジトリであることを前提とする
