# ユーザー knowledge の参照

方針決定・設計判断・実装を行なう場面では、判断を確定させる前に以下の手順で検証しなければならない

- 関連する既存知見を search_knowledge で検索する
- ヒットしたら read_knowledge で本文を読む
- knowledge の内容を踏まえて、判断が妥当か検証する

# コード実装の共通方針

コードを実装・修正する際は、以下の方針に従うこと。

## 作業フロー

以下の順序で作業を進めること。順序を入れ替えてはならない。

### Step 0: 仕様の確認
- 実装に着手する前に、実装対象の仕様を確認する。以下の情報源を確認し、実装の根拠となる仕様を把握すること：
  - issueの記述・参照元issue・関連PR
  - CLAUDE.mdに記載された設計原則・制約
  - CLAUDE.mdに「実装前に必ず確認する情報源」が定義されている場合、そのすべてを確認する
  - 関連する既存実装（互換性が求められる場合は、互換対象のコードを実際に読んで挙動を把握する）
  - 外部サービスのドキュメント（API仕様等、必要に応じて）
- 仕様が不明確な場合は、推測で実装に進まず確認する

### Step 1: テスト駆動で実装する

**REQUIRED**: `test-driven-development` スキルに従い、RED-GREEN-REFACTOR で実装する。要点は「失敗するテストを書く → 失敗を観察する → 通す最小限のコードを書く → 整える」。鉄則・失敗パターン・チェックリストの詳細は同スキルに置いてあるので、判断に迷ったら参照する。

### Step 2: 検証（証拠を確認してから完了とする）

完了・成功を主張する前に、その根拠となるコマンドを**この場で実行し、出力を読んでから**主張する。「通るはず」「たぶん大丈夫」で終わらせない。

- `npm run check` / `npm run typecheck`（プロジェクトの該当コマンド）を実行し、exit 0・0 エラーを出力で確認する
- 全テストが通ることを確認する（前回の実行結果や推測を根拠にしない）
- `code-review` スキルでセルフレビューする
- 指摘や失敗があれば修正し、Step 1 に戻る

## 厳守事項

これらの原則の具体的な判断基準は knowledge の `tech/design` に置いてある。判断を確定させる前に、冒頭「ユーザー knowledge の参照」の手順で該当する知見を必ず読むこと。以下には原則だけを挙げ、具体的な条件は列挙しない。

- **指示された範囲のみ変更すること**（指示にない範囲の「改善」や「リファクタリング」を追加しない）
- **コードを自然言語に翻訳しただけのコメントを書くことを禁止**（例: `// iを1増やす` `// userを返す` 等。コードを読めばわかることをコメントしない）
- **既存のコードベースのスタイル・パターンに従うこと**
- **不要な防御的コードを書かない** — 内部コードの保証を信頼すること
- ソフトウェアエンジニアリングの原則に従い、堅牢性・変更容易性・低認知負荷を意識したコードを書くこと
- 適切なモジュール分割を行うこと

**堅牢性**
- エッジケースを必ずテストする（null/undefined、空配列、境界値など）
- エラーは握りつぶさず、適切に伝播・通知する
- フェイルファスト — 異常な状態は早期に検出して即座に失敗させる
- 型で不正な状態を表現不可能にする（any/asを避け、型を最大限活用する）
- 引数や共有データを直接変更しない（不変性を保つ）

**変更容易性**
- SOLID原則に従う
  - 関数の変更理由が複数ある場合は分割する
  - 新しいケースの追加にswitch/ifの分岐追加で対応せず、パターンで拡張する
  - 親クラスのメソッドを空実装やthrowでオーバーライドしない
  - インターフェースは利用者が必要とするメソッドだけを含める
  - 外部依存（DB・API・ファイルシステム）は差し替え可能にする
- 重複を避ける（DRY） — コードの見た目ではなく知識・ロジックの重複を排除する
- 隠れた依存・グローバル状態を避け、依存を明示的にする

**低認知負荷**
- 変数・関数名は意図が一目でわかる名前にする（略語・汎用名を避ける）
- 早期リターンを活用し、ひとつの関心事の処理が終わり結果が導かれた時点で関数を抜ける
- 条件分岐が複雑にならない設計をする

## 完了前チェックリスト

完了を報告する前に、以下を満たしていることを確認する。

- [ ] Step 0 で確認した仕様どおりに実装した（指示にない変更を足していない）
- [ ] `test-driven-development` のチェックリストを満たした
- [ ] check / typecheck をこの場で実行し、exit 0・0 エラーを出力で確認した
- [ ] `code-review` でセルフレビューし、指摘に対応した
