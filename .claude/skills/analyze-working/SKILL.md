# セッションログ分析

## 引数
$ARGUMENTS

引数のパース:
- 第1引数: 期間指定（`7d`, `3d`, `2w` 等）。省略時は `7d`
- 第2引数以降: 追加の分析観点（自由記述）。省略可能

例:
- 引数なし → 直近7日間、デフォルト観点のみ
- `3d` → 直近3日間
- `7d チームエージェントの指示品質` → 7日間 + 追加観点「チームエージェントの指示品質」

## デフォルトの分析観点（常に実施）

1. **非効率なコミュニケーション** — ユーザーが同じ指示を繰り返している、修正指示が多い、中断が多い、要件の誤解による手戻り等
2. **定型化できる作業** — 繰り返し出現する作業パターンでスキル化・スクリプト化できそうなもの
3. **スキル遵守率** — 既存スキルのルールが守られなかったケース

追加の分析観点が引数で指定されていれば、上記に加えてその観点でも分析する。

## 実行手順

### Step 1: セッションログファイルの収集

1. 現在のプロジェクトのパスを特定する（`pwd` の結果を使用）
2. プロジェクトパスから対応するディレクトリ名を推定する（先頭の `/` を除去し、残りの `/` を `-` に置換）
3. `~/.claude/projects/` 配下で、そのディレクトリ名に前方一致するディレクトリを列挙する（worktree用の派生パスを含めるため）
4. 引数の期間を `find -mtime` 用の日数に変換する（`7d` → `-mtime -7`、`2w` → `-mtime -14`）
5. 対象ディレクトリ内の `.jsonl` ファイルを `find` で列挙する
6. `subagents/` 配下のファイルは除外する（メインセッションから内容は追える）

```bash
# 期間変換の例
# 7d → 7, 3d → 3, 2w → 14, 1w → 7
# find コマンド例:
find "$PROJECT_DIR" -name "*.jsonl" -not -path "*/subagents/*" -mtime -7 -type f
```

### Step 2: セッションログの読み取り

各 `.jsonl` ファイルからユーザーメッセージを抽出する。jqを使用:

```bash
# ユーザーメッセージの抽出
jq -r 'select(.type == "user") | .message.content | if type == "string" then . elif type == "array" then .[0].text // "" else "" end' "$LOG_FILE"
```

注意事項:
- 大きいファイル（5MB超）は `head -c 2000000` と `tail -c 2000000` でサンプリングする
- セッション数が多い場合（10件超）は、Agentツールを使ってバッチ分析を並列化する

### Step 3: 各セッションの要約

各セッションについて以下を把握する:
- セッションの目的（何をしようとしていたか）
- ユーザーメッセージの流れ（やりとりの回数、修正指示の回数）
- team-managerやサブエージェントが使われていた場合はその構成

### Step 4: 分析観点ごとの横断分析

デフォルト観点 + 追加観点で、全セッションを横断的に分析しパターンを洗い出す。

### Step 5: レポート出力

以下の形式でレポートを出力する:

1. **セッション一覧** — 日付、目的、規模（メッセージ数）の表
2. **各分析観点ごとの発見事項** — 具体的な事例を引用しながら記述
3. **改善提案** — 具体的なアクション（スキル追加、CLAUDE.md修正、hooks設定等）

## 注意事項

- セッションログはユーザーのプライベートデータ。外部送信は絶対に行わない
- jqコマンドを活用してJSONL解析を効率化する
- 分析結果は簡潔に。冗長な説明は不要
- ファイルの作成・編集は行わない（分析・レポート出力のみ）
