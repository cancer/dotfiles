# モデルと推論量の選択

呼び出し側が `--model` / `--effort` を指定しなかったときに読む。値は下記の検証済みの表から選び、推測で書き換えない。

## この環境のモデル（検証済み）

**モデルは `gpt-5.6-luna` の 1 つだけを使う。** 定型から高度な実装まで、推論量を唯一のつまみとしてこの 1 モデルで扱う。

上位モデル（`gpt-5.6-sol` など）は段に置かない。**選択肢として並べた時点で、条件を書いても上位が選ばれる。** 「探索範囲を決め切れない場面に限る」と条件を明記していたが、やることが明確な依頼でも `sol` が選ばれた（2026-08-19 実測）。試験運用の 19 発注も上位偏重（`sol` 7 / 中間 9 / `luna` 2）で、ログ自身の評価が「`sol` 不要」と判定したものが 2 件あった。`luna` の 2 件はどちらも一度で合格している。

上位モデルが埋めない失敗も実測で出ている。テスト網羅の不足は `sol` でも残り、起動失敗を「完了」と報告する完了誤認は `sol` で起きた。差し戻しでは、上位モデルの初回出力に対する修正が `luna` + `low` で通っている。単価は 25 倍である。

**`luna` + `max` で抜けない依頼に当たったら、モデルを上げずに止まり、ユーザーへ報告して指示を仰ぐ。** そこで必要なのはたいてい上位モデルではなく、依頼文の作り直しか、タスクの分割である。上位モデルを使う判断は人間が行う。

GPT-5.6 が使えなくなったら、`~/.codex/models_cache.json`（`visibility: list` かつ `supported_in_api: true`）から代替を 1 つ選び、選んだ ID と理由をここへ反映する。

## 推論量（検証済み）

実効レンジは `none, low, medium, high, xhigh, max`。「推論を最小に」は `none` を指す。**`minimal` は GPT-5.6 の API が 400（unsupported_value）で拒否する。**

推論量は `herdr agent start` の `--` 以降に `-c model_reasoning_effort=<値>` として渡り、Codex 本体へ直接届く。値を検証して弾く層が間に無いので、Codex が受理する値はそのまま使える。

## Fast モード

Fast モードは Codex の `service_tier` である（"1.5x speed, increased usage"、速度を使用量で買う設定）。`luna` は単価が低いので速度を買う。**`-c service_tier=priority` を渡す。**

**起動時に毎回明示し、`~/.codex/config.toml` の値に任せない。** TUI の Fast トグルがこのキーを書き戻すので、ユーザーが対話セッションで切り替えた状態が委任へ漏れてくる。

オンに `fast` ではなく `priority` を渡すのは、`fast` が [`codex-rs/core/config.schema.json`](https://github.com/openai/codex/blob/main/codex-rs/core/config.schema.json) で legacy とされており、ワイヤ上はどちらも `priority` になるからである。オフを表す `default` はスキーマにしか出てこない（`models_cache.json` は各モデルの対応ティア表であり、語彙の一覧ではない）。対応ティアに無い値（`flex` など）を渡してもオフにはなるが、`warning: Configured service tier ... will be omitted from requests.` が毎回ペインに出るので使わない。

## 段

`luna` + `high` を基本に置き、難度に応じて推論量を上下させる。

| 段 | 指定 | 使う場面 |
|---|---|---|
| 定型 | `luna` + `none` | 変更対象が明示され、実装方法が一意。リネーム、指定された API 変更への追従、既知のパッチ適用、formatter/lint の自動修正、指定した検査コマンドの実行 |
| 単純 | `luna` + `low` | 対象ファイルを探す必要がある。軽い判断を伴う。`none` で一度失敗した |
| 小さめ | `luna` + `medium` | 複数ファイルにまたがるが、設計判断は依頼文で埋まっている。テストの追加位置や境界条件まで指示できている |
| 基本 | `luna` + `high` | 既定。どこから始めるか迷ったらここ |
| やや高度 | `luna` + `xhigh` | 構造の理解が要る、影響範囲が広い |
| 高度 | `luna` + `max` | `xhigh` で合格しなかった。正しさの判定が難しい実装（時刻ずれや有効期間の境界、並行処理、データ移行）や、新規ファイルを含む大きな実装で構成から組ませる場合。探索の範囲を依頼文で決め切れない調査もここ |

`max` が上限である。ここで抜けないなら、上げ先を探すのではなく依頼文を作り直すか、タスクを分割する。

## 基本より下げてよいか

依頼文を書き終えた時点で Codex に残る裁量の量で決める。**ファイル数・行数は段の根拠にしない。** 実測では中間段が、コード・設定・生成型・仕様書・テストにまたがる 7 ファイルの移行を、指示していない箇所を grep で見つけて直すところまで一度で通している。

対象ファイルの特定から任せる、実装方針が複数ありうる、境界や基準を決め切れていない、のいずれかが残るなら下げない。発注前に次を確認する。

- 設計判断（基準・境界・命名・分割の方針）を依頼文で決め切ったか
- 環境依存の事実（外部 API の応答、DB の制約、既定バージョン）を先に確かめて依頼文へ貼ったか。確かめられない詳細は書かない
- 禁止したい文字列や構文にバリアントがあるなら列挙したか（目的の記述は網羅性を保証しない）

書けていない状態で段を上げても差し戻しは減らない。書き切れたなら 1 つ下げて発注する。

**Codex が検査を実行できないことを段の根拠にしない。** サンドボックスで開発サーバーが起動しないのは起動フラグ（`-c sandbox_workspace_write.network_access=true`）で解消できる環境の設定であって、判断の難度ではない。開けられる検査は開けて走らせ、段は依頼文に残る裁量だけで決める。

## luna の限界（実測）

- **`medium` 以下では、既存の記述や実装から値を導出する計算を任せない。** 日付・期間・境界・件数が成果物の核になるなら、確定値を依頼文へ書く。実測で `luna` + `medium` が期間計算の日付を 1 週ずらし境界も誤ったが、確定値を渡すと同じ段で一度で通った。導出そのものが未確定の判断なので、渡さずに投げた時点で段を下げる前提を外している
- **報告の裏取りが甘い。** コードを読めば分かる内容を推測で報告することがある（既存の分岐が例外を再生成すると報告したが、実際は呼び出しが `try` の外にあり再生成されなかった）。この差は依頼文での自己検査の指示と、差分の機械的な照合で埋める。格上げでは埋まらない

## 差し戻しの段

差し戻しで段を上げるのは既定にしない。範囲が限定された時点で必要な判断量は減っている。実測でも、上位モデルの初回出力に対する差し戻しが中間段で通り、その差し戻しが `luna` + `low` で通っている。

- 原因が依頼文の不備 → 同じ段で条件を書き直して出し直す
- 修正範囲が特定のファイル・関数に絞れた → 1 つ下げる
- 原因不明のまま 2 回落ちた → 1 つ上げる。`max` まで上げても抜けないなら、そこで止めてユーザーへ報告する

## コスト

単価は段の選択の決め手にしない。推論量を上げれば消費は増えるが、発注 1 件のコストは、差し戻し 1 回で発生する検収サイクル（差分の読み直し、テストの再実行、追加の依頼文）より小さい。安いから下げるのではなく、依頼文で迷う余地を消せたから下げる。

2026-07-30 の値下げ後、`luna` の 100 万トークンあたりの単価は出力 $1.2 / 入力 $0.2（[OpenAI の告知](https://openai.com/index/advancing-the-price-performance-frontier-with-gpt-5-6/)、2026-07-31 確認）。上位モデルは出力 $30 / 入力 $5 で 25 倍にあたる。段から外した判断の材料として残す。
