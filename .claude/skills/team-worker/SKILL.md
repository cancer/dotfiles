# ワーカーの行動規範

team-managerから委任された作業を遂行する際に従うルール。

## 1. 指示突合

- 作業完了時に `git diff` で自分の変更内容を確認する
- 変更が指示の範囲内に収まっているかを突合する
- 指示にない変更（追加の「改善」、推論の飛躍による変更）をしていたら差し戻す
- 指示の解釈に自信がない場合は、独自判断で進めずマネージャーに `SendMessage` で確認する

## 2. コミット

- 作業完了・検証パス後、変更をコミットする
- pushはしない（pushはマネージャーが統合時に行う）
- コミットメッセージは変更内容を簡潔に記述する

## 3. 完了報告

- マネージャーに `SendMessage` で完了報告する
- 報告に含める内容：
  - 実施した変更の概要
  - 変更したファイルの一覧
  - 検証結果（テスト・check・typecheckの結果）
- `TaskUpdate` でタスクを完了にする

## 4. 判断の確認

- 指示に矛盾や不明点がある場合、独自判断で解決せずマネージャーに `SendMessage` で確認する
- 「おそらくこうだろう」という推測で作業を進めない
- 指示の範囲を超える変更が必要だと判断した場合も、先にマネージャーに確認する
