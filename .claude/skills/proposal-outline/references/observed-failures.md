# proposal-outline に関係する観測済みの失敗

ここには proposal-outline の手順または修正モードに関係する失敗だけを記録する。対応する指示は、各 F 番号または承認済み state.txt のユーザー発言に結び付ける。

## F1: 読者役の改善案から未合意のサービスを追加した

- 観測した失敗: 読者役シミュレーションの改善案を取り込み、「受注前の無償実データ検証」をサービスとして追加した。
- 出典: Codex セッションのユーザー発言「先方担当者のリアクションをシミュレーションしたら…無償と明記する」、handoff §2「絶対に受注前の無償実データ検証を約束しない」。
- 適用: 修正に提供内容や約束の追加が必要なら、questions.md に記録して止める。

## F6: 見出しから何を伝えるか分からなかった

- 観測した失敗: 「基本構成」という見出しが何を伝えたいのか分からなかった。
- 出典: Codex セッションのユーザー発言「基本構成って何を伝えたいの？」。
- 適用: C1 の各スライド見出しは、そのスライドの結論を言い切る文にする。

## F8: 社内向けの注記が対外資料に残った

- 観測した失敗: 社内検討用の注記「社内検討用・金額等は調整中」が対外資料に残った。
- 出典: Claude セッション 19843cb7 のユーザー発言「社内検討用・金額等は調整中 > これ消して」。承認済み state.txt の指示「社内用『業界理解メモ』に出典付きで残し、確認済み事実と不明点を分ける。スライドには載せない」。
- 適用: 業界理解メモは社内用とし、outline.md のスライド本文に含めない。

## F9: 合意していない費用負担を提案に加えた

- 観測した失敗: サーバー代を弊社負担とする費用構成を提案に加えた。
- 出典: Claude セッション 2269f83e のユーザー発言「サーバー代は弊社が負担する。つまり…持ち出しなさい、と？」。
- 適用: 修正で費用または負担者を新たに決める必要がある場合は、questions.md に記録して止める。

## F10: ユーザーが否定した指標を入れた

- 観測した失敗: ユーザーが否定した時間計測を提案に入れた。
- 出典: handoff §2「時間計測はしない（ユーザーの明示訂正）」。
- 適用: 修正にユーザーが否定した条件や指標を戻さない。事実確認が必要なら questions.md に記録して止める。

## F13: 依頼内容と無関係な企業情報を提案の根拠にした

- 観測した失敗: 依頼内容と関係しない企業情報（業績など）から提案を導いた。
- 出典: 承認済み state.txt のユーザー発言「特に『最近の業績が◯◯なので、XXするといいです』みたいな、依頼内容と無関係な企業情報を持ち出すことは認めない」。
- 適用: 依頼内容と無関係な業績・経営方針・ニュースを提案の根拠にせず、依頼外の領域を提案しない。
